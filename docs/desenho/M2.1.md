# Desenho M2.1: botão "Copiar URL da API" na página de chaves

Issue #16. Base: `upstream/main` (patch ao upstream, separado; nada no upstream durante a trava). A PR #6
do fork trazia uma versão, mas ela **já está no `upstream/main`** como "Copy base URL" (`#2020`): copia
`k.apiUrl ?? k.baseUrl`, a URL do **provedor**, com as chaves `setup.copyUrl`/`setup.copiedUrl`. R4 pede
outra coisa — a URL do **gateway**, `<baseUrl>/chat/completions`. As duas coexistem; este desenho não
muda a existente.

## Objetivo

Acrescentar, junto da chave unificada e da URL base do gateway, um botão que copia
`<baseUrl>/chat/completions`, com as chaves de texto `copyApiUrl` e `copiedApiUrl` nos 60 locales. O botão
só aparece quando há `baseUrl`; falha de cópia é informada sem entrar no estado "copiado".

## Risco

`baixo`: componente local do painel, duas chaves de texto e um teste; sem banco, autenticação, limites,
endpoints ou ids de modelo novos. O único ponto delicado é não confundir este botão com o de URL do
provedor que já existe.

## Requisitos e testes do plano

R4, R18. T2.1, T2.2.

## Contrato

### Tela

Rota: a página de chaves (`KeysPage.tsx`), na seção `UnifiedKeySection` — onde a chave unificada e o
`baseUrl` do gateway já são exibidos (`keys.baseUrl`). Nenhuma rota nova.

`baseUrl` é o já existente na seção:

```ts
import.meta.env.DEV ? `http://${window.location.hostname}:${__SERVER_PORT__}/v1` : `${window.location.origin}/v1`
```

O botão recebe esse valor e copia `apiUrlFromBase(baseUrl)` = `baseUrl.replace(/\/+$/, '') + '/chat/completions'`
(remove barras finais para não produzir `//chat/completions`). Nenhum outro endpoint é inventado.

Estados:

| Estado | O que aparece |
|---|---|
| `baseUrl` presente | botão com `aria-label = t('keys.copyApiUrl')` e ícone de link, ao lado do botão de copiar chave |
| após cópia bem-sucedida | `toast.success(t('keys.copiedApiUrl'))`, ícone de check por 1500 ms e `aria-label` trocado para o texto "copiado" |
| cópia falhou (`copyText` devolve `false`) | `toast.error(t('common.copyFailed'))`, sem ícone de check e sem mudança de `aria-label` |
| sem `baseUrl` | nenhum botão |

O botão usa `copyText` de `client/src/lib/clipboard.ts` (já lida com origem não segura) e os primitivos
`Button`/`Tooltip` e as variáveis de `client/src/index.css`. Não abre diálogo, não navega e não mexe na
chave. O botão "Copy full key" e o botão "Copy base URL" dos provedores seguem intactos.

### i18n

Chaves novas, no namespace `keys` (onde vivem `keys.baseUrl`, `keys.copyKey`, `keys.copiedKey`):

| Chave | `en` | `pt-BR` |
|---|---|---|
| `keys.copyApiUrl` | `Copy API URL` | `Copiar URL da API` |
| `keys.copiedApiUrl` | `API URL copied` | `URL da API copiada` |

As duas chaves entram nos **60** arquivos de `client/src/i18n/locales/` no mesmo commit, com o mesmo valor
e tipo. `en.json` é a fonte; os outros 58 recebem tradução com sentido (não todas com o mesmo texto
inglês), respeitando a terminologia de `docs/TRANSLATION.md` (em particular "API" em latim, e as regras
de zh-CN/zh-TW). Nenhum placeholder `{}` é introduzido. Validador: `npm --prefix client run check:i18n`.

Nada.

## Especificação para o TDD do dev

Componente novo `client/src/components/keys/copy-api-url-button.tsx` com a prop `baseUrl?: string | null`
(assim o caso "sem baseUrl" é testável sem mexer em `window.location`), usado por `UnifiedKeySection`.
Teste em `client/src/components/keys/copy-api-url-button.test.tsx` (`@vitest-environment jsdom`, padrão de
`provider-list-copy-url.test.tsx`): `vi.mock('@/lib/clipboard')`, `vi.mock('@/lib/toast')`,
`I18nProvider initialLocale="en"`, `vi.useFakeTimers()` e limpeza no `afterEach`.

- **DM2.1-1** — dado `baseUrl='http://127.0.0.1:3001/v1'`, quando clico no botão, então `copyText` é
  chamado uma vez com `http://127.0.0.1:3001/v1/chat/completions`, `toast.success` recebe `API URL copied`,
  e o `aria-label` passa a ser `API URL copied`. **Escrever primeiro e ver falhar.**
- **DM2.1-2** — dado `baseUrl='http://127.0.0.1:3001/v1/'` (barra final), quando clico, então o texto
  copiado é `http://127.0.0.1:3001/v1/chat/completions`, sem `//`.
- **DM2.1-3** — dado `baseUrl` vazio, `null` ou ausente, quando monto o componente, então nenhum botão com
  `aria-label="Copy API URL"` existe.
- **DM2.1-4** — dado `copyText` que devolve `false`, quando clico, então `toast.error` recebe
  `common.copyFailed`, `toast.success` não é chamado e o `aria-label` continua `Copy API URL`.
- **DM2.1-5** — dado uma cópia bem-sucedida, quando avanço 1500 ms com fake timers, então o ícone e o
  `aria-label` voltam ao estado inicial (o timeout é limpo no unmount).
- **DM2.1-6** — dado o conteúdo de `en.json` e `pt-BR.json`, quando procuro as duas chaves, então os valores
  são exatamente os da tabela acima; dado qualquer um dos outros 58 locales, quando roda
  `npm --prefix client run check:i18n`, então a saída é 0 e não há `missing keys`, `extra keys`, tipo
  divergente ou placeholder diferente.
- **DM2.1-7** — dado `UnifiedKeySection` montado com a seção carregada, então o componente novo recebe o
  `baseUrl` calculado pela seção (os testes existentes da página seguem verdes).
- **DM2.1-8** — dado `client/src/components/keys/provider-list-copy-url.test.tsx`, quando roda, então passa
  sem edição: o botão de URL do provedor continua copiando `k.apiUrl ?? k.baseUrl` com
  `setup.copyUrl`/`setup.copiedUrl`.

## Riscos e pontos de atenção

- **Duas URLs, dois botões:** o que já existe em `provider-list.tsx` copia a URL do **provedor**; o novo
  copia a URL do **gateway**. Não renomear o antigo, não reaproveitar `setup.copyUrl` para o novo e não
  pôr o novo na linha do provedor — DM2.1-8 protege isso.
- `baseUrl` em DEV usa `__SERVER_PORT__` (definido pelo build); em produção usa `window.location.origin`.
  Testar o componente com a prop, não alterando `window.location` no jsdom.
- O sufixo é `/chat/completions`, não `/v1/chat/completions`: o `baseUrl` já termina em `/v1`.
- Acessibilidade: `aria-label` muda junto com o ícone; sem `aria-label`, o teste E2E não encontra o botão.
- i18n: os 60 arquivos mudam juntos; um único locale esquecido faz `check:i18n` sair 1. A revisão de
  tradução é humana — o validador só confere estrutura.

## Fora do escopo

- Grok e xAI, que também tocam o painel de chaves: M2.2 (#5).
- Botão de URL do provedor (`setup.copyUrl`) e os testes dele: já no upstream, não mexer.
- Copiar URL de outros endpoints (`/v1/responses`, `/v1/messages`): não pedido por R4.

## Decisões

- ADR-016: o botão de R4 copia a URL do gateway e vive na seção da chave unificada; o botão de URL do
  provedor do upstream permanece separado, com chaves de i18n próprias.
