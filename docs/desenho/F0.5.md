# Desenho F0.5: marca de versão dos patches no painel

Issue #11. Base para o desenho: `main` do fork. O patch de código (`Dockerfile`) nasce de `upstream/main`
quando o fluxo de patch abrir (F0.7); o wrapper `freellmapi-databoar-build` mora em `~/.local/bin` e é
**do operador** (issue #11) — não entra em branch de patch. Nada no upstream durante a trava.

## Objetivo

Fazer o painel mostrar a tag do build que carrega os nossos patches. O servidor já lê `FREEAPI_VERSION`
em tempo de execução e `/api/settings/version` já publica o valor; falta o build gravar a tag no ambiente
do contêiner e o wrapper passá-la como `--build-arg`.

## Risco

`padrão`: uma linha de `ARG`/`ENV` no `Dockerfile` e um `--build-arg` no wrapper do operador; sem dados,
segredos, autenticação ou troca automática do serviço (o wrapper só troca a imagem com ordem do usuário).

## Premissas conferidas (leitura de código e prova local, 2026-11-27)

- `server/src/lib/app-version.ts`: `getAppVersion()` prefere `FREEAPI_VERSION` não vazio; só depois cai
  para `desktop/package.json`. `server/src/routes/settings.ts` expõe `GET /api/settings/version` e o painel
  (`update-reminder.tsx`, `updates-dialog.tsx`) consome esse endpoint. Nenhum código novo é necessário no
  servidor nem no painel.
- `Dockerfile` já usa o padrão `ARG FREELLMAPI_COMMIT_SHA` → `ENV FREELLMAPI_COMMIT_SHA=…` na camada final;
  o mesmo padrão serve para `FREEAPI_VERSION`. `docker-compose.yml` não define `FREEAPI_VERSION`, então o
  valor do `ENV` não é sobrescrito no contêiner.
- O wrapper atual compila o ref pedido (`git -C "$REPO" archive … "$REFSHA"`); a premissa antiga do plano
  ("compila o checkout atual e usa `--ref` só para o texto") vinha de uma versão sobrescrita do script e
  **está obsoleta**. Não refazer essa parte do wrapper.
- Rodado `--print-version --ref origin/main` num repositório sintético mínimo (refs `upstream/main` e
  `origin/main`, sem distantas reais): saída `image: localhost/freellmapi:up-<sha8>.databoar-<sha8>`.
  O formato canônico é esse, com rótulos opcionais `.label` — **não** `<tag>-<n>-g<sha>` como diz T0.5 no
  plano. A revisão de T0.5 é pedido ao PM (ver "Fora do escopo").

## Requisitos e testes do plano

R17. T0.5 (com a correção do formato da tag, acima).

## Contrato

### Saída do build (efeito observável)

`freellmapi-databoar-build --print-version --ref <ref>` imprime
`image: localhost/freellmapi:up-<upstream sha8>.databoar-<ref sha8>[.<rótulo>...]` e sai 0, sem construir
e sem tocar o `:3001`. `--no-install` constrói a imagem com a tag e não troca o serviço. Sem `--no-install`
o wrapper continua com o seu comportamento atual (backup, troca, espera por healthy, `/api/ping`) e só com
ordem do usuário.

### Variável no contêiner

`Dockerfile`, na camada final (junto de `FREELLMAPI_COMMIT_SHA`):

```dockerfile
ARG FREEAPI_VERSION
ENV FREEAPI_VERSION=${FREEAPI_VERSION}
```

O wrapper passa `--build-arg "FREEAPI_VERSION=$TAG"` ao `podman build` (mesmo `TAG` impresso por
`--print-version`). Se o build for feito sem esse `--build-arg`, `FREEAPI_VERSION` fica vazio e o painel
continua mostrando a versão de `desktop/package.json` — comportamento de hoje, preservado.

### Resposta da API (inalterada)

`GET /api/settings/version` → `200 {"version": "<FREEAPI_VERSION do build>"}`; com valor vazio/ausente,
`{"version": "<versão de desktop/package.json>"}`; sem nenhuma das duas, `{"version": null}`.

## Modelo de dados

Nada.

## Especificação para o TDD do dev

- **DF0.5-1** — dado um repositório sintético pequeno (num `mktemp` com `trap` de limpeza, com refs
  `upstream/main` e `origin/main` e `FREELLMAPI_DATABOAR_LABELS` apontando para arquivo vazio), quando
  roda `freellmapi-databoar-build --print-version --ref origin/main`, então imprime
  `image: localhost/freellmapi:up-<sha8>.databoar-<sha8>` com os SHAs curtos das duas refs e sai 0.
  **Premissa já conferida pelo arquiteto; é o primeiro passo da sequência, para o dev a confirmar no host.**
- **DF0.5-2** — dado `FREEAPI_VERSION` definido antes da primeira chamada, quando chama
  `getAppVersion()` (teste existente em `app-version.test.ts`), então devolve esse valor; com espaço em
  branco, cai para a versão de `desktop/package.json`. Teste já existe; não duplicar.
- **DF0.5-3** — dado um app de teste (`createApp`, banco `:memory:`) com `FREEAPI_VERSION='up-abc12345.databoar-def67890.zeroclassifier'` no ambiente, quando faz `GET /api/settings/version`,
  então recebe 200 e `{"version":"up-abc12345.databoar-def67890.zeroclassifier"}`; sem a variável, recebe
  a versão de `desktop/package.json`. Usar `resetAppVersionCache()` no `beforeEach`/`afterEach` e restaurar
  a variável no `finally` (padrão de `app-version.test.ts`). Porta `0` em `127.0.0.1`, nunca `3001`.
- **DF0.5-4** — dado o `Dockerfile`, quando lê as duas linhas adicionadas, então há exatamente um
  `ARG FREEAPI_VERSION` e um `ENV FREEAPI_VERSION=${FREEAPI_VERSION}` **depois** do `ARG FREELLMAPI_COMMIT_SHA`
  (camada final, depois dos `COPY`s, para não invalidar cache). Teste estático: `grep -c` com contagem 1.
- **DF0.5-5** — dado o texto do wrapper, quando procura a linha do `podman build`, então há
  `--build-arg "FREEAPI_VERSION=$TAG"` com o mesmo `TAG` usado na linha `image:`; nenhuma outra linha do
  wrapper muda (`git diff -U0` só nessa linha). O wrapper não é editado pelo dev: esta é a prova de que a
  linha do operador está presente antes do teste T0.5.
- **DF0.5-6** — dado o diff, quando roda `git diff --name-only upstream/main...HEAD`, então só aparece
  `Dockerfile` (o wrapper e `docs/` não entram no branch de patch).

## Especificação para a aceitação do QA

Caixa-preta, sem importar módulos. O operador executa o build com `--no-install` e sobe o contêiner
**sem publicar a porta 3001 no host** (`podman run --rm -p 127.0.0.1::3001 …`), consultando a porta
efêmera que o podman escolher.

- **AF0.5-1** — dado `freellmapi-databoar-build --print-version --ref <ref> --no-install`, quando o build
  termina, então a tag impressa contém `.databoar-<sha8 do ref>` e o build sai 0 sem tocar o `:3001`.
- **AF0.5-2** — dado a imagem construída com `--build-arg FREEAPI_VERSION=<tag>`, quando consulto
  `GET /api/settings/version` na porta efêmera, então o corpo traz exatamente `<tag>`; o painel mostra a
  mesma string na linha de versão.
- **AF0.5-3** — dado a mesma imagem sem o `--build-arg`, quando consulto o endpoint, então a versão é a
  de `desktop/package.json` (comportamento atual preservado; o build "sem patches" não inventa versão).

## Sequência

1. **Antes do dev:** DF0.5-1 no host (prova do formato da tag; já feita pelo arquiteto).
2. **`test:`** DF0.5-3 e DF0.5-4: o teste de rota e o teste estático do `Dockerfile`. Ambos falham pelo
   motivo certo (a `ENV` ainda não existe).
3. **`feat:`** acrescentar as duas linhas no `Dockerfile` (camada final, depois de
   `ARG FREELLMAPI_COMMIT_SHA`). DF0.5-3 e DF0.5-4 verdes.
4. **Fora do branch:** o operador acrescenta `--build-arg "FREEAPI_VERSION=$TAG"` ao wrapper; DF0.5-5.
5. **Verificação:** AF0.5-1 a AF0.5-3 com `--no-install` e porta efêmera. Gate do PM no SHA exato:
   `npm ci`, `npm run test:migrations`, `npm test`, `npm run lint`, `npm run build`.

## Riscos e pontos de atenção

- **Não trocar o `:3001`:** todo build desta tarefa usa `--no-install`; a imagem de produção do usuário
  só é trocada por ordem dele. A prova de versão usa porta efêmera, nunca `3001`.
- `getAppVersion()` guarda cache: um teste que muda `FREEAPI_VERSION` depois da primeira leitura precisa
  de `resetAppVersionCache()`. Em produção o valor é fixo desde o boot, então o cache é correto.
- Um valor vazio/`"   "` não conta como versão; não substituir por um valor inventado.
- Rótulos do wrapper (`patch-labels.tsv`) são parte da tag e devem aparecer no painel sem escaping.
- A tag não é semver; o painel trata a versão como string (o updates-dialog compara com a release do
  GitHub — isso é comportamento existente e fora desta tarefa).

## Fora do escopo

- Edição do wrapper pelo dev ou pelo framework: é arquivo do operador, fora do repositório.
- Revisão de T0.5 no plano (`<tag>-<n>-g<sha>` → formato `up-…databoar-…`) e da issue #11: pedido ao PM.
- Proteção do `main` (F0.3) e gate local (F0.10).

## Decisões

- ADR-011: a versão marcada entra no contêiner como `FREEAPI_VERSION` via `ARG`/`ENV` do `Dockerfile`; o
  wrapper é do operador; o formato canônico da tag é o do wrapper.
