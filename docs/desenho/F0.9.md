# Desenho F0.9: fork verde no `docker.yml` e CI que não roda à toa

Issue #25. Base: `main` do fork. **Um PR único no fork junto com a F0.1** ("fork verde"; a F0.1 já
tem o commit `10882950`). Mesclado por `merge-green`. As mudanças nos workflows são só do fork e não
vão ao upstream (ADR-001), com uma exceção possível no fim.

## Objetivo

O `docker.yml` volta a passar no fork: o nome da imagem passa a sair em minúsculas, e o fork só
constrói a imagem nos PRs, sem publicar. O `ci.yml` e o `docker.yml` deixam de rodar num push para
o `main` que só mexe em `docs/**`, PDFs ou `.claude/agent-memory/**`. Nenhuma regra fica mais frouxa
para código.

## Risco

`alto`: é infraestrutura de CI e publicação de imagem. O diff é pequeno (2 arquivos, cerca de +14 e
−3 linhas). Um erro aqui deixa os PRs sem a checagem de build ou faz o fork publicar imagem sem
querer.

## Causa (confirmada pelo PM no log da execução 45306686322)

`failed to parse ref "ghcr.io/FabioLeitao/freellmapi": invalid reference format: repository name
(FabioLeitao/freellmapi) must be lowercase`. A linha 15 do `docker.yml` é
`IMAGE: ghcr.io/${{ github.repository_owner }}/freellmapi`, e o dono do fork tem maiúsculas. O nome
entra em `outputs: type=image,name=${{ env.IMAGE }},…` mesmo quando `push=false`, por isso falha
também nos PRs. Reproduzido sem rede pelo arquiteto, com uma imagem `FROM scratch` no podman:
`ghcr.io/FabioLeitao/freellmapi:probe` dá `invalid reference format: repository name must be
lowercase`, e `ghcr.io/fabioleitao/freellmapi:probe` é aceito.

## Requisitos e testes do plano

R12, R24. T0.10. T0.2 vem junto com a F0.1, no mesmo PR.

## Contrato (efeitos por evento)

| Evento | `ci.yml` | `docker.yml`, job `Build (…)` | `docker.yml`, job `Merge manifest and push` |
|---|---|---|---|
| PR para o `main` (fork ou upstream) | roda, sem filtro | roda nas duas plataformas, só constrói (`push=false`), com o nome em minúsculas | não roda (já era assim) |
| push no `main` do **fork** só com `docs/**`, `**/*.pdf` ou `.claude/agent-memory/**` | não dispara | não dispara | não dispara |
| push no `main` do **fork** com código | roda | job pulado (`if:`) | job pulado |
| push no `main` ou tag `v*` no **upstream** | como hoje | como hoje (constrói e publica por digest) | como hoje (publica o manifesto) |

Publicação, **padrão reversível e pendente de decisão do usuário (ADR-009):** o fork não publica no
ghcr; só o repositório `tashfeenahmed/freellmapi` publica. **Para o fork publicar em
`ghcr.io/fabioleitao/freellmapi`,** troque nas duas linhas `if:` do desenho
`github.repository == 'tashfeenahmed/freellmapi'` por
`(github.repository == 'tashfeenahmed/freellmapi' || github.repository == 'FabioLeitao/freellmapi')`.
O nome já sai em minúsculas, e o `latest` continua só em tag.

## Modelo de dados

Nada.

## Diff esperado

`.github/workflows/ci.yml` (+2, −0), no bloco `on.push`, depois de `branches: [main]`:

```yaml
    # Fork-only (F0.9, R24): a push touching only docs, PDFs or agent memory skips CI. PRs always run.
    paths-ignore: ['docs/**', '**/*.pdf', '.claude/agent-memory/**']
```

`.github/workflows/docker.yml` (+12, −3):

```diff
@@ on.push, depois de tags: ['v*.*.*']
+    # Fork-only (F0.9, R24): a push touching only docs, PDFs or agent memory skips this workflow.
+    paths-ignore: ['docs/**', '**/*.pdf', '.claude/agent-memory/**']
@@ bloco env do topo (3 linhas, inclusive a vazia depois dele)
-env:
-  IMAGE: ghcr.io/${{ github.repository_owner }}/freellmapi
-
@@ jobs.build, depois de name: Build (${{ matrix.platform }})
+    # Fork (F0.9): build on PRs only; push builds and publishing stay with the upstream repo.
+    if: github.event_name == 'pull_request' || github.repository == 'tashfeenahmed/freellmapi'
@@ jobs.build.steps, antes do passo "Platform slug"
+      # Registry names must be lowercase; the owner may not be (F0.9).
+      - name: Image name
+        run: echo "IMAGE=ghcr.io/${GITHUB_REPOSITORY_OWNER,,}/freellmapi" >> "$GITHUB_ENV"
+
@@ jobs.merge
-    if: github.event_name != 'pull_request'
+    if: github.event_name != 'pull_request' && github.repository == 'tashfeenahmed/freellmapi'
@@ jobs.merge.steps, primeiro passo
+      - name: Image name
+        run: echo "IMAGE=ghcr.io/${GITHUB_REPOSITORY_OWNER,,}/freellmapi" >> "$GITHUB_ENV"
+
```

Nada mais muda: nem `permissions`, nem as versões das actions, nem os outros passos.
`${{ env.IMAGE }}` e `${IMAGE}` continuam onde estão: o valor gravado em `$GITHUB_ENV` chega aos
passos seguintes, como o `PLATFORM_PAIR` deste mesmo arquivo já faz. O nome vem da variável de
ambiente `GITHUB_REPOSITORY_OWNER`, e não de `${{ }}` no shell, para não abrir injeção de template.
A minúscula é feita pelo `${…,,}` do bash, o shell padrão do runner.

- **DF0.9-6** — `grep -n "IMAGE" .github/workflows/docker.yml`: nenhuma linha `IMAGE:` no nível do workflow; dois passos `Image name`; os usos `${{ env.IMAGE }}` e `${IMAGE}` intactos.

Construir o `Dockerfile` do projeto localmente (`podman build -t ghcr.io/fabioleitao/freellmapi:local .`) é opcional. Precisa de rede (imagem base e `npm ci`) e leva minutos. Ele só prova que o `Dockerfile` constrói, coisa que o upstream já prova no CI dele.

**O que só o GitHub prova:**

- os filtros de gatilho (T0.10): push só de documentação sem nenhuma execução, push de código com o CI;
- o `if:` dos jobs: no fork, os dois jobs do `docker.yml` aparecem como pulados num push e rodam num PR;
- o build real com BuildKit nos runners nativos `ubuntu-24.04` e `ubuntu-24.04-arm`, inclusive o cache `gha`;
- os checks "Build (linux/amd64)" e "Build (linux/arm64)" verdes no PR, que é o que o `merge-green` exige.

## Especificação para a aceitação do QA

Aceitação: não se aplica. Não há comportamento do produto, e o efeito só é observável no GitHub. Quem
confere é o PM, no PR e depois do merge:

1. No PR: os checks `Test & build (Node 20/22/24)`, `Build (linux/amd64)` e `Build (linux/arm64)` verdes, e nenhum job `Merge manifest and push`.
2. Depois do merge (T0.10, refeito): o T0.10 do plano fala em "branch de teste", mas os dois workflows só disparam em push para o `main`, então o teste vale no `main`. O primeiro commit do PM só com `docs/` ou memória, enviado **sem** `[skip ci]`, não cria execução: `gh run list --repo FabioLeitao/freellmapi --workflow ci.yml --branch main --limit 3 --json headSha,event` não mostra o SHA dele. O próximo merge de código cria uma execução do `ci.yml`, e a do `docker.yml` tem os jobs pulados.

## Sequência (passos mecânicos para o dev externo)

O branch é o da F0.1 (`tarefa/F0.1-tirar-migracao-nvidia`), e os commits entram depois do `10882950`.

1. **Antes de editar:** rodar DF0.9-1 e DF0.9-2 e guardar as saídas como "antes".
2. **`ci.yml`:** inserir as 2 linhas de `paths-ignore` no bloco `on.push`. Commit `ci: skip fork CI on docs-only pushes (F0.9)`.
3. **`docker.yml`, gatilho e nome:** as 2 linhas de `paths-ignore`, a remoção das 3 linhas do bloco `env` e os dois passos `Image name` (no `build`, antes de `Platform slug`; no `merge`, como primeiro passo). Commit `ci(docker): lowercase image name (F0.9)`.
4. **`docker.yml`, publicação:** as duas linhas `if:` (a nova no `build`, a trocada no `merge`). Commit `ci(docker): build-only on the fork (F0.9)`.
5. **Provas:** DF0.9-1 a DF0.9-6, comparando com o passo 1. O PM confere o diff contra a seção "Diff esperado" linha a linha.
6. O PM abre o PR único "fork verde" (F0.1 + F0.9) depois do gate da F0.1 e do "vai" do usuário.

## Riscos e pontos de atenção

- **Não baixar o rigor:** nada de `continue-on-error`, `|| true`, remover job nem trocar versão de action. O `if:` no `build` pula o job só em push no fork. Nos PRs ele roda como antes, e o conteúdo do push já foi construído no PR.
- **`[skip ci]` num commit de código pula o CI inteiro.** Com o `paths-ignore`, o PM não precisa mais dele nos commits de documentação, e ele nunca vai num commit de código.
- **Sincronização com o upstream:** o upstream pode mexer nessas mesmas linhas. O conflito se resolve mantendo a intenção deste desenho: nome em minúsculas, fork sem publicar e `paths-ignore` só no `push`.
- **Proteção do `main` (F0.3):** os checks obrigatórios precisam ser os de PR (`Test & build …`, `Build (…)`). Um commit só de documentação não gera check, e a F0.3 tem de permitir esse push direto do PM.
- `paths-ignore` não vale para tag: o GitHub não avalia filtro de caminho em push de tag. No fork, tag também não publica (os jobs estão pulados).

## Fora do escopo

- Gate local `scripts/check-all.sh`: F0.10 (#26).
- Proteção do `main`: F0.3 (#10).
- Levar ao upstream só o conserto da minúscula (útil a qualquer fork de dono com maiúsculas): candidato a patch depois da trava. O `if:` de publicação e o `paths-ignore` são só do fork.

## Decisões

- ADR-009: o fork constrói a imagem nos PRs e não publica (padrão reversível, pendente do usuário).
